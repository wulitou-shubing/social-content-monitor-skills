# 从安装到首次运行

这份教程写给第一次接触 Codex Skill 的使用者。完成后，你会得到两项能力。

- 把单个视频链接、本地视频或录音转成文字稿和 SRT 字幕
- 监控指定平台账号，把新作品和口播文案保存到飞书多维表格

建议先跑通单个视频转写，再配置账号监控。这样遇到问题时，很容易判断是转写环境、平台登录还是飞书配置出了问题。

## 开始前先准备

你需要准备以下内容。

- 已安装并能正常使用的 Codex
- Python 3.10 或更高版本
- `ffmpeg`
- 一个你有权访问的视频链接或本地媒体文件
- 一个飞书多维表格
- 正常可用的平台和飞书登录会话

监控功能还需要飞书官方 `lark-cli`、`lark-shared` Skill、`lark-base` Skill，以及可以访问目标平台的浏览器控制能力、官方 API 或已授权连接器。

你不需要一开始就把所有依赖弄明白。可以把下面这段话交给 Codex，让它先检查环境。涉及安装软件、下载模型或使用浏览器登录状态时，Codex 应当先征得你的同意。

```text
我要使用 social-content-monitor-skills。请检查这台电脑是否已经具备 Python 3.10、ffmpeg、飞书 lark-cli、lark-shared、lark-base 和视频转写所需的 Python 依赖。

只做检查，不要直接安装。请用小白能看懂的方式告诉我缺什么，以及每一项是做什么的。
```

## 第一步 安装两个 Skill

把下面这段话发给 Codex。

```text
请从下面两个 GitHub 地址安装 Skill，并在安装后检查它们是否能够被识别。

https://github.com/wulitou-shubing/social-content-monitor-skills/tree/main/skills/video-audio-transcribe
https://github.com/wulitou-shubing/social-content-monitor-skills/tree/main/skills/social-content-monitor-to-lark
```

安装结束后，你应该能在可用 Skills 中看到下面两个名字。

- `video-audio-transcribe`
- `social-content-monitor-to-lark`

如果只想做视频转文字，安装 `video-audio-transcribe` 就够了。

## 第二步 测试单个视频转写

先找一个你有权下载和转写的视频链接，然后把下面这段话发给 Codex。

```text
请使用 video-audio-transcribe 处理下面的视频。

这里换成视频链接

请保留带时间戳的原始文字稿，同时生成 SRT 字幕。识别完成后告诉我检测到的语言、视频时长、使用的模型和生成文件的位置。人名、数字或品牌名不确定时请标出来，不要猜。
```

处理本地文件时，把链接换成文件路径即可。

```text
请把这个本地视频转成文字稿和 SRT 字幕。

/这里换成你的视频文件路径.mp4
```

如果只想提取 MP3，可以这样说。

```text
请从这个视频中提取 MP3，保留原视频，音频码率使用 192k。

/这里换成你的视频文件路径.mp4
```

一次正常的转写会得到带时间戳的文字稿和 SRT 字幕。第一次使用某个 Whisper 模型时，可能需要下载模型，因此等待时间会比以后长。

## 第三步 新建飞书多维表格

新建一个飞书多维表格和数据表。字段名称可以自定义，但第一次使用建议照着下面的名称创建，后续配置会更简单。

| 字段名称 | 推荐类型 | 是否必需 | 说明 |
| --- | --- | --- | --- |
| 唯一键 | 单行文本 | 是 | 推荐保存平台和内容 ID 的组合 |
| 平台 | 单行文本 | 是 | 抖音、小红书或其他平台 |
| 内容ID | 单行文本 | 是 | 平台提供的作品编号 |
| 内容类型 | 单行文本 | 是 | 视频、图文或其他类型 |
| 标题 | 多行文本 | 是 | 作品标题 |
| 发布日期 | 日期 | 是 | 作品发布时间 |
| 链接 | 超链接 | 是 | 原作品地址 |
| 作者 | 单行文本 | 是 | 创作者名称 |
| 原始文案 | 多行文本 | 是 | 作品发布时自带的文字 |
| 口播文案 | 多行文本 | 是 | Whisper 转写结果 |
| 转写状态 | 单行文本 | 是 | pending、completed、not_applicable 或 failed |
| 失败原因 | 多行文本 | 是 | 失败时保存排错信息 |
| 点赞数 | 数字 | 否 | 平台能够可靠读取时保存 |
| 评论数 | 数字 | 否 | 平台能够可靠读取时保存 |
| 收藏数 | 数字 | 否 | 平台能够可靠读取时保存 |
| 分享数 | 数字 | 否 | 平台能够可靠读取时保存 |
| 播放量 | 数字 | 否 | 平台能够可靠读取时保存 |

创建完成后，复制飞书多维表格链接。不要把私人表格链接公开贴到 GitHub、论坛或聊天群。

## 第四步 登录并检查飞书权限

把下面这段话发给 Codex。

```text
请检查我的飞书 lark-cli 登录状态和 lark-base 权限。然后读取下面这个多维表格的真实数据表和字段结构，只做检查，不要创建、修改或删除记录。

这里换成飞书多维表格链接
```

检查结果中应当能看到你的数据表名称和字段。若提示没有权限，先按 Codex 给出的授权步骤完成登录，再重新检查。

## 第五步 创建监控配置

仓库提供了一份不含私人信息的 [示例配置](../skills/social-content-monitor-to-lark/assets/config.example.json)。

真实配置应当放在 Skill 文件夹和 Git 仓库之外。这样以后更新 Skill 或把仓库公开到 GitHub 时，不容易误上传私人账号、飞书链接和本地路径。

你可以让 Codex 帮你生成配置。

```text
请根据 social-content-monitor-to-lark 的示例配置，帮我在 Skill 文件夹和 Git 仓库之外创建一份真实监控配置。

需要监控的账号
1. 平台名称和账号主页链接
2. 平台名称和账号主页链接

飞书多维表格链接
这里填写

数据表名称
这里填写

每天计划检查的时间
08:00 和 16:30

先向我展示准备写入的配置内容。账号稳定 ID、字段映射或保存位置无法确定时请说明，不要猜。
```

配置中每个账号默认应当先保持停用。确认主页地址和稳定账号 ID 后，再把需要测试的一个账号改为启用。不要一开始同时打开很多账号。

## 第六步 校验配置

配置创建完成后，让 Codex 运行仓库自带的校验工具。

```text
请使用 social-content-monitor-to-lark 自带的 validate_config.py 校验我的监控配置。只做校验，不要开始监控。发现问题时请告诉我具体字段和修改方法。
```

校验通过只说明配置格式正确。飞书字段是否匹配、平台登录是否有效、账号主页是否能读取，还需要在下一步实际验证。

## 第七步 首次手动运行

第一次不要立刻创建定时任务，也不要直接导入全部历史作品。建议先对一个账号建立基线。

基线可以理解为记住当前最新作品的位置。以后监控只处理它之后出现的新作品，不会把整个主页的历史内容一次性灌进飞书。

```text
请使用 social-content-monitor-to-lark 和我的监控配置手动运行一次。

这次只测试一个已启用账号。建立基线，不导入历史作品，不创建定时任务，不绕过验证码或访问限制。

完成后请分别告诉我发现了什么、是否写入飞书、是否进行了转写，以及有没有登录、字段或平台校验问题。
```

首次运行没有新增内容通常是正常的，因为流程刚刚记录了基线。你可以等目标账号发布新作品后再次手动运行，也可以在明确知道后果的情况下要求导入少量历史作品。

## 第八步 验证一条新作品

当账号出现新作品后，再手动运行一次。

```text
请使用同一份配置再运行一次监控。只处理基线之后的新作品，最多检查每个账号最新的 5 个候选。请核对作者名称和稳定账号 ID，避免把推荐内容或别人的作品写进飞书。
```

一条视频作品正常完成后，飞书里应该能看到以下结果。

- 作品元数据已经写入
- 唯一键形如 `<平台>:<内容ID>`
- 原始文案保留在原始文案字段
- 口播文案写入同一条记录
- 转写状态为 `completed`

图文作品没有可以转写的语音时，转写状态应当是 `not_applicable`，这不代表失败。

若下载或转写失败，原记录应当保留，转写状态应当是 `failed`，失败原因字段会留下排错信息。修复问题后再次处理，应更新同一条记录。

## 第九步 再考虑定时监控

只有在手动运行和飞书写入都验证成功后，才建议创建定时任务。

```text
我已经确认手动监控、去重、转写和飞书写入都正常。请根据配置中的时区和时间创建定时监控。

没有新内容时不用通知我。出现验证码、登录失效、字段不匹配、下载失败、转写失败或飞书写入失败时必须通知我。不要自动点赞、关注、评论、私信或发布内容。
```

创建完成后，要求 Codex 告诉你任务名称、运行时间、使用的时区和出错时的通知方式。

## 常见问题

### 安装后找不到 Skill

先确认安装地址指向具体的 Skill 文件夹，不是只给了仓库首页。然后让 Codex 列出当前可用 Skills，必要时重新加载工作区或重新开始一个任务。

### 提示没有 ffmpeg

`ffmpeg` 负责读取视频和处理音频。请让 Codex 说明当前系统适合哪种安装方式，并在你确认后再安装。

### 第一次转写很慢

第一次可能正在下载 Whisper 模型。`small` 模型适合日常使用，`medium` 或 `large-v3` 通常更慢，也需要更多磁盘空间和计算资源。

### 抖音或其他平台要求验证

停止当前监控，在正常浏览器中完成登录或安全验证，再重新运行。不要要求 Skill 绕过验证码、模拟浏览器指纹或规避访问频率限制。

### 飞书提示字段不匹配

先让 Codex 重新读取真实数据表和字段结构，再调整配置里的 `field_map`。不要只凭浏览器地址栏中的一段字符猜 Base token 或数据表 ID。

### 飞书里出现重复作品

检查唯一键是否稳定保存为 `<平台>:<内容ID>`。如果平台拿不到稳定内容 ID，流程只能退回使用规范化作品链接，可靠性会弱一些。

### 新作品写入了，但没有口播文案

先看转写状态。`not_applicable` 代表作品没有可以转写的语音，`failed` 代表下载或识别发生问题。根据失败原因处理后，应更新原记录，不要新建一条记录。

### 文案里的人名或数字不准确

Whisper 的结果是听写草稿。保留带时间戳的原始稿，根据视频原声人工复核人名、品牌、数字和专业词。无法确认的内容应当标出来，不要凭上下文猜写。

## 更新 Skill

仓库更新后，可以把两个安装地址再次发给 Codex，并明确要求从 GitHub 获取最新版、检查变更和重新验证。更新前应保留仓库外的真实配置和运行状态，不要用示例配置覆盖它们。

```text
请从下面两个地址检查并更新已经安装的 Skill。更新前不要删除我的真实配置和运行状态。更新后请告诉我改了什么，并重新检查两个 Skill 是否可用。

https://github.com/wulitou-shubing/social-content-monitor-skills/tree/main/skills/video-audio-transcribe
https://github.com/wulitou-shubing/social-content-monitor-skills/tree/main/skills/social-content-monitor-to-lark
```

## 隐私和使用边界

- 只监控你有权访问的账号和内容
- 真实配置放在 Git 仓库与 Skill 文件夹之外
- 不公开飞书私人链接、账号清单、本地路径、Cookie 或登录凭证
- 不绕过验证码、登录验证、访问频率或付费限制
- 不让监控流程自动点赞、关注、评论、私信或发布
- 分享转写结果前确认内容版权、平台规则和个人信息风险

如果你只是想验证功能，先用自己的公开视频、测试表格和一个测试账号。跑通一条记录之后，再逐步增加平台、账号和运行频率。
