# Launch checklist

This checklist separates repository-owned publishing from posts that use a maintainer's personal identity.

## Repository-owned actions

- [ ] Push the documentation, safety, community, demo, and validation changes
- [ ] Confirm the validation workflow passes on `main`
- [ ] Publish GitHub release `v0.1.0`
- [ ] Upload `assets/social-preview.jpg` as the GitHub social preview
- [ ] Create a welcome Discussion with the tested install command and contribution areas
- [ ] Confirm Discussions, private vulnerability reporting, secret scanning, and push protection are enabled
- [ ] Confirm the repository appears on skills.sh after a real CLI install
- [ ] Submit the public repository to AgentSkill.sh
- [ ] Submit to no more than two relevant curated lists after reading their contribution rules

## Personal publishing actions

- [ ] Review the drafts in `promotion/social-posts.md`
- [ ] Choose two communities where the post genuinely fits
- [ ] Publish the longer technical post before the short social posts
- [ ] Reply to installation questions with reproducible commands and public examples
- [ ] Do not claim adoption, performance gains, or platform support that has not been verified

## Measurements

Record the numbers before publishing, after 24 hours, after 7 days, and after 30 days.

| Date | Stars | Unique visitors | Unique cloners | Referring sites | Install questions | Confirmed successful installs |
| --- | ---: | ---: | ---: | --- | ---: | ---: |
| Baseline | 0 | 0 | 0 | None reported | 0 | 1 local clean-room CLI test |

GitHub traffic data may lag. Use the same measurement time each day and keep screenshots or exported notes when comparing channels.
